# 更新日志

版本号与 `versionCode` 均取自 `AndroidManifest.xml`。

## 1.42 — versionCode 37

- 修复（用户反馈）：系统升级后编辑页里的「开始编辑」按钮、点卡片选栏的提示和灰罩都不见了，点了也没反应；现在恢复正常。
- 同时修复同一原因导致的另一处退化：从系统样式切回自定义时确认左栏卡片的那一步一度失效，可能在切换样式后显示成别的卡。
- 日志里会明确写出「按名字找宿主方法一个都没找到」的情况，下次系统再改这些内部结构时，出问题能直接从日志看出来，不必等发现功能没了。

## 1.41 — versionCode 35

- 修复（用户反馈）：在系统样式下把左栏选成某张卡，再直接切到「自定义」、不点「开始编辑」就确定，桌面会被换成别的卡，或两栏顺序与编辑页预览不一致。
- 现在打开编辑页时，预览显示的就是你配置里的那两张卡；卡池里暂时取不到某张卡时会按配置直接重建，不再沿用上一次的旧卡，因此点确定不会把你选好的两栏冲掉。
- 另外在切到「自定义」的那一刻会按当前配置对齐一次两栏内容，并通知桌面重读一次，让桌面与预览保持一致。
- 这一步只对齐内存里的数据、不改配置、不写档案；如果不想让它动手，把配置里 features 的 compose_realign 设为 false 即可立即关掉（无需卸载重装）。

## 1.40 — versionCode 34

- 修正上一版检测日志的一个缺陷：切回系统样式时没能记下系统卡组的卡片类型，导致"这次的卡和系统卡组重复"永远判不出来，实验功能本来要靠它决定要不要动手。
- 现在每次从系统样式切到自定义时都能正确比对；用户可见行为不变（这一步只写日志，不改桌面、不改配置）。
- 实验功能仍默认关闭：只有在配置 features 里把 perturb_rebuild 设为 true 才会做实际切换。

## 1.39 — versionCode 33

- 试做（用户反馈）：从「系统工具」切到「自定义」后，桌面两栏仍可能左右相反，只有重启桌面才恢复。这一版在切到自定义时，会让桌面先短暂回到系统两栏、再换成你的自定义两栏，借这次真实变化让桌面重建。
- 这一步是可关的实验功能，默认关闭：目前只是把「什么时候该重建」记进日志，不做任何实际切换，日常使用与上一版完全一样。
- 打开方式：在配置 features 里把 perturb_rebuild 设为 true。每次切换最多重建一次，同一种配置 24 小时内不会重复，12 小时内最多 5 次；中途退出或重启也只会回到正确的自定义两栏。
- 若打开后卡面丢失或不想看到这次短暂切换，把 perturb_rebuild 改回 false 即可立即关掉（无需卸载重装）。

## 1.38 — versionCode 32

- 修复（用户反馈）：从「系统工具」样式切到「自定义」后，桌面两栏会左右相反，只有重启桌面才恢复；现在切完样式后桌面会自己重建一次两栏，顺序与编辑页预览一致。
- 这一点只在样式或两栏选择刚变过时触发一次，之后不再反复重建，日常使用没有额外的闪烁。
- 如果遇到卡面丢失或不想让桌面重建，把配置里 features 的 rebuild_inject 设为 false 即可立即关掉（无需卸载重装）。

## 1.37 — versionCode 31

- 修复（用户反馈）：从「系统工具 + 应用建议」切到「自定义」后直接完成，桌面两栏会跟编辑页预览左右相反；现在桌面始终与预览一致。
- 不需要重新选卡：已有的自定义两栏配置原样保留，切换样式不会覆盖或丢失。
- 切换样式、重启桌面之后两栏顺序也不会回退（上一版重启后仍可能保持相反）。
- 修复：编辑页点「完成」后桌面不跟着变（或要等很久才变）；现在完成时会让桌面立即重读一次两栏顺序，与预览保持一致。
